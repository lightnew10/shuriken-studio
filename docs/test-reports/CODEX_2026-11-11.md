## Limites et retour arrière

- Le sandbox Windows à lecture restreinte a refusé le profil avec « Restricted read-only access requires the elevated Windows sandbox backend ». La commande de contrôle n'a pas créé le fichier interne ; le témoin extérieur est resté intact (`.cache/codex-shell-canary.json`). Le code refuse l'exécution sans sandbox et ne tente aucune élévation. La réussite d'une commande réelle dans ce profil, les sentinelles réseau et la disparition de tout descendant d'une telle commande restent à qualifier sur un poste équipé.
- La parité complète avec Claude reste ouverte pour le Python libre Blender. Le parcours natif du Kiln personnel, l'installeur Windows et un compte Claude réel ne sont pas exercés par ces essais. Les erreurs Kiln sont couvertes par une régression sur un service simulé ; la modélisation réelle a utilisé Blender headless.
- Le plafond de tokens dépend de la fréquence des notifications App Server. L'écriture compare le contenu avant renommage et protège contre les autres runs via le bail Shuriken ; un programme tiers ne participe pas à ce bail.
- Pour désactiver Codex, réassigner les rôles à Claude puis désactiver le fallback dans les réglages. Pour revenir au code précédent, garder ce travail en l'état et repartir de `7400f17` dans un dossier séparé, après sauvegarde des données de test.
